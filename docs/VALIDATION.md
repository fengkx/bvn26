# 验收与对照计划

实际已取得的局部对照与未验收范围以 [STATUS.md](STATUS.md) 为准。以下定义验收要求；格式示例和局部通过结果不能代替完整验收。

新增角色、招式或修复原版差异，按 [角色一比一还原与缺陷验收 SOP](CHARACTER_PARITY_SOP.md) 执行，尤其保留同一对战内的连续施放与实例生命周期回归。

## 证据层级

1. 原 SWF 字节/时间轴/配置：证明文件和数值的来源。
2. 反编译脚本：帮助理解逻辑，但复杂分支需回到字节码或运行验证。
3. 已记录环境的原播放器轨迹：用于行为基准；录屏只能验证可见结果，不能冒充内部变量。
4. 模拟器轨迹：辅助，不自动等同于原播放器。差异必须标明来源。
5. Godot 重放和截图：用于与同输入的基准比较。

每个案例保存主程序及依赖哈希、播放器/引擎版本、OS、渲染/缩放、键位、模式/地图/人物/形态、初始状态、输入、随机来源和运行时间。所有脚本插桩应在副本上进行，记录插桩 diff。

## 对战对照方法

先使用 AI 关闭、固定初始站位、随机条件受控的最小场景；记录原版实际随机消费或明确排除不参与该案例的随机条件。重放相同输入，按已确认的调度阶段抓取数据。

实现或修改机制前先完成 [SOURCE_FIRST.md](SOURCE_FIRST.md) 的五问。重击、破防、连击、命中火花与必杀黑底/立绘横幅还须走完 [HIT_RECEIVE_SOP.md](HIT_RECEIVE_SOP.md) 的步骤 A→E。未完成闸门的改动即使能玩、schema 合法、单测变绿，也不算对照通过。

比较顺序：输入锁存 → 动作与源帧 → 创建/移除的区域 → 碰撞候选顺序 → 伤害/状态/`hits`/破防 → 位置 → 视听（火花、顿帧、闪光、连击板、`bar2`、黑底、立绘横幅）。只比较最后血量容易遗漏抵消的错误。

回归断言原版不变量（源路径能指到的标签、帧、高度、是否进入下一标签），禁止把「猜的顶点」「只有命中才播后续」写成期望后再改实现去凑。发现实现与源不一致时改实现或编译器，不放宽阈值、不改基准输出。

离散状态与命中时点要求精确一致。浮点位置使用 M0 测得的基准精度，不以全局四舍五入抹平漂移。长序列重复 10,000 个逻辑 tick 用于发现漂移/泄漏，只有测试中确有相关风险时纳入常规回归。

## 视觉与声音

在相同 600×400 坐标、相同逻辑帧、相同舞台缩放下捕获。先检查帧号、注册点、透明边界、层级和颜色，再检查滤镜/矢量栅格化。像素差图、分区域差异和人工叠加检查共同使用。

原位图/裁切内容必须正确。抗锯齿误差不能掩盖轮廓位移、错误动画帧或判定反馈；存在未解决可见差异时，记录为未完成。任何数值阈值先在已正确样本上确定并记录，不在修不好的样本上临时放宽。

声音逻辑触发 tick 与循环点应匹配。浏览器输出延迟独立测量，不把设备延迟当技能事件时序差异。比较受击/必杀多个声音的叠加、暂停/恢复和角色切换后的清理。

声音来源要能追到源标签：对照时先核该剪辑那一帧的 `StartSound` `soundId` 与 `SOUNDINFO` 音量，再听观感。命中/防住/元素/必杀火花（`XG_*` 第 1 帧）与角色/我爱罗援助时间轴上的 `StartSound` 已按 `soundId` 接线；剪辑 `unloadMovie` 时火花音随节点停。日番谷基础形态和 `XG_bs`/`XG_cbs` 的 `in_point`/`out_point` 与左右声道静态包络已编译成 PCM 区间，特效声音由源帧调度器单独触发；采样范围和单次播放回归通过，原播放器波形及设备延迟仍待对照。`stageSound` BGM 已接入选图后的对战，逐地图编译的清单保留原版随机选曲顺序；不能用「听起来差不多」的替代音顶上。

`stageSound` 的选曲要按源顺序对随机：先 `p2selt` 曲目（`Math.random() < 0.8`），再 `bleach.mp3`/`naruto.mp3`（`< 0.5`），否则地图曲目。对照时记录这一两次随机消费，不能只核最终播了哪首。

当前可跑的检查：

```bash
python3 tools/verify.py
python3 tools/check_handoff.py
python3 -m unittest discover -s tools/tests
python3 tools/test_helper_super_overlap.py --godot /path/to/godot
godot --headless --path godot -s res://tests/player_controller_smoke.gd
godot --headless --path godot -s res://tests/player_visual_smoke.gd
godot --headless --path godot -s res://tests/combat_smoke.gd
godot --headless --path godot -s res://tests/menu_smoke.gd
godot --headless --path godot -s res://tests/stage_sound_smoke.gd
```

无头音频用 dummy 驱动，`AudioStreamPlayer` 起过声音的用例退出时会报 `ObjectDB` 泄漏与 `resources still in use`；这是驱动不混音导致 playback 不回收，不代表用例失败，但也不得用它掩盖真实的节点泄漏。

## 内容覆盖策略

- 两名切片角色：全部基础形态动作、镜像、空中、墙角、相互命中、边界取消输入。
- 每个基础角色/形态：动作遍历、标准对手、镜像对局、至少一条连招/受击链、已知特殊机制。
- 每个援助：左右方向、攻击/被打断/回收、与自身角色限制的原版行为。
- 每张地图：左右边界、相机缩放、平台/特殊地形、前后景和音乐。
- 每种模式：从入口到结果再返回，包含超时、重开、设置和必要关卡变化。
- 组合测试优先覆盖已知交互风险与不同机制，不把全两两穷举作为每次提交都必须运行的默认流程。

## 失败处理和发布门槛

发现首个差异时保存输入、tape、两侧轨迹、截图和源路径，分类为数据、调度、碰撞、数值、随机、渲染、平台或基准自身。先修复具体原因，只重跑受影响测试；公共核心变更再扩展相关回归。

发布候选必须给出 AT-01～16 的结果和证据链接。无证据/格式示例/仅脚本导出成功均不得填 passed。没有原版参照时可以发布“未完成验证的原型”，但不能称“一比一复刻完成”。
