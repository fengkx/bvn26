# 架构与运行时设计

本文是实施方案，尚无对应 Godot 实现。需求编号以根目录 [SPEC](../SPEC.md) 为准。

## 模块边界

| 模块 | 输入 → 输出 | 责任与限制 |
|---|---|---|
| 离线导入器 | 原 SWF + 脚本索引 → 中间数据/图集/声音/问题清单 | 解析符号、帧、矩阵、裁切和事件；不把脚本字符串交给运行时执行 |
| 数据编译器 | 中间数据 → 经校验的 Godot 资源 | 解析资源依赖、hook 白名单、动作和形态引用；拒绝未解析项 |
| InputRouter | 键盘事件 → 每逻辑帧按键集合与边沿 | 保留同帧按下/释放的事件序号；记录原按键与逻辑动作映射 |
| Simulation | 初始状态 + 输入 + 随机值 → 新状态/事件 | 处理行为、位移、命中、资源值、回合；不直接绘图或播放音频 |
| ActionRunner | 动作时间轴 + 状态 → 帧事件/形状状态 | 游戏专用帧事件解释，不实现通用 AVM |
| CollisionSystem | 变换后的原判定区域 → 有序候选命中 | 复现矩形/点判定调用形态与优先级，不依赖物理信号到达顺序 |
| Presentation | 状态快照 + 视听事件 → 场景显示 | 负责图层、镜像、相机、特效、HUD、声音；不得反写战斗状态 |
| Replay/Trace | 初始条件/按键/随机序列 ↔ 重放与轨迹 | 逐帧步进、截图、首次差异定位；开发环境功能 |
| WebShell/Settings | 浏览器交互 ↔ 生命周期与设置 | 点击启动、焦点/全屏/音频解锁、设置保存；无第三方游戏平台依赖 |

未来工程位置建议为 `godot/`，下分 `core/`、`presentation/`、`ui/`、`data/`、`debug/`。转换缓存放 `build/`，最终网页放 `dist/web/`；这些目录当前均未生成。

## 逻辑时间与更新顺序

主频为 30 Hz。渲染可以更快，但只能读取逻辑快照；不能插入额外攻击判定或改变技能帧时长。采用 Godot 固定物理回调时须将频率设为 30，并只保留一个战斗时钟。采用自行累积的时钟时不得同时使用第二套 `_physics_process` 推进战斗。

待 M0 验证的工作模型：输入锁存 → 当前帧的放置/移除与脚本事件 → 控制/移动 → 碰撞与有序受击 → 状态提交 → 提交后渲染事件。**这不是对 Flash 真实调度顺序的结论。** M0 必须通过探针确定 `DoAction`、`onClipEvent(enterFrame)`、`onEnterFrame`、帧跳转和子时间轴启动的实际先后，并据此调整 `ExecutionProfile`。没有这份记录，不进入完整连招验收。

执行记录至少包含 `tick`、`phase`、`event_order`、符号实例 ID、源帧、目标状态。`gotoAndPlay` 是否在同一逻辑步执行目标帧、停止时间轴后 `enterFrame` 是否继续，均需实测。禁止统一成“所有事件都下一帧执行”。

`setInterval`/`getTimer` 使用单独时钟域；先记录原调用点与暂停行为，再映射到确定性调度。30 Hz 下某些毫秒定时器并非整数帧间隔，应保留累计余量。UI 计时、AI 随机决策、受击硬直、受伤语音冷却和动画停顿不得默认共用一个暂停开关。

## 状态和身份

- `MatchState`：模式、地图、回合、时间、胜负、暂停域、随机流位置、玩家/援助/特效实例。
- `FighterState`：稳定实体 ID、配置 ID、形态、动作/源帧、位置与速度、朝向、血量/气量、受击计数、无敌/暂停标志、当前判定区域和取消资格。
- 源 `_root`/`_parent` 路径通过明确对象引用迁移。动态创建的攻击和特效使用稳定实例 ID；不使用 Godot 节点创建顺序作为命中优先级。
- 原 `for..in`、数组枚举和重叠攻击候选返回顺序会影响伤害，应记录原顺序并明确编码。
- `undefined`、`null`、NaN、字符串/数字比较、大小写和未初始化变量逐项审查。JSON 不支持 NaN，使用明确的“未定义”状态；不得一律改成 0。

## 数值与坐标

SWF 坐标以 TWIP 存储；转换时保留原矩阵、注册点、嵌套变换及位图 smoothing 标志。模拟使用显式浮点标量与清晰的单位；Godot 向量、显示属性或缓存导致精度改变时须对照轨迹。不要提前断言全部动态位置都是 0.05 像素的倍数。

基准中 Y 轴与画面一致向下，但场景地面和角色局部坐标可为负。将地图原点、角色注册点与屏幕相机变换分开，不能把 `_root.floorY = -25` 误当作整个画面地面位置。

初始实现复现原 `MovieClip.hitTest` 用法：对象/对象通常依赖对象边界，点/形状调用具有不同语义。实际碰撞对象常是不可见判定区域，不是人物可见像素。透明对象是否参与边界、镜像后的区域、嵌套矩阵和边界恰好接触须用探针验证。

## 动画与渲染

离线产物保留符号实例、深度、父子关系、帧标签、持续帧数、变换、颜色变换、mask/filter/blend、可见性及声音事件。纯装饰序列可烘焙为图集，但不得把角色碰撞与行为埋进 GIF。角色形态共享素材时，保留共享引用而不是复制整套图集。

同一张原图可生成多个裁切区域；每个区域同时保存原注册点与裁切偏移，避免人物脚底跳动。像素角色的过滤模式依照原位图属性确认；矢量 UI 的栅格化独立处理，不能全局强制最近邻后宣称视觉相同。

必杀冻结应分别控制攻击者、受击者、援助、特效和场景；相机由独立状态驱动。击中反馈的暂停长短是逻辑，不交给动画播放器自由时间缩放决定。

## 随机与重放

原版 `Math.random()` 若由 AI、声音、天气等共享，删掉某个消费者会改变后续决策。初期记录随机值消费序列；实现侧提供 `RandomSource` 接口。受控轨迹使用记录的 tape。只有种子而无原版随机算法/消费顺序，不能声称与原版 AI 逐帧一致。

比较核心战斗时先关闭 AI 并固定对手输入，再逐步纳入援助、形态和随机决策。展示层不能额外消耗战斗随机值；若要拆流，必须保留原语义或明确记录不匹配。

## 错误与资源生命周期

缺少动作、事件 handler、声音或判定区域时输出实体、动作、源符号/帧和资源哈希，阻止 该内容进入发布构建。角色切换、回合结束、菜单返回必须回收攻击实例、暂停标志、定时器与音频对象。焦点丢失时暂停比赛并清空 held keys；恢复时重置浏览器时间锚点，不补算失焦期间的战斗。
