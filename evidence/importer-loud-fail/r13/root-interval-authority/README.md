# Recorded online root interval delivery

`online_timer_authority.gd` now tracks every root interval registration by its independent numeric ID, rather than the mutable `_root.feiint`/`feiint2` handle fields. Overwriting a handle leaves its earlier ID and captured callback alive; explicit cancellation removes only the named registration. Root deliveries use the existing `after_actor_advance` supplier phase and are sorted by due time, then ID within the root queue. BODY timeout registrations retain their existing behavior.

Each root delivery re-arms its deadline from the authoritative elapsed-time sample and authored millisecond delay. This deliberately follows the **existing online stability policy**, shared by countdown/nextfight: at most one delivery per interval per sample, re-anchored after a late/backgrounded sample. It does not simulate wall time from animation frame counts or claim exact native Flash wall-phase/catch-up parity. Native reference tests establish repeating independent IDs/captured-function lifetime; the online supplier phase policy remains separately documented in the authority.

Deadline snapshots are version2, explicitly contain root deadlines, and reject malformed entries before mutation. Restoring a battle followed by its authority rebinds the restored root queue. A new match queue may restart numeric IDs at1; it gets new deadlines rather than inheriting the retired queue's schedule. This is internal timer-owner bookkeeping, not an implementation of AVM1 MovieClip reference equality.
