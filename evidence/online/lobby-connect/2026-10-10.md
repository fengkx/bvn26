# Lobby connection delivery failure — 2026-10-10

## Observed evidence

The user supplied `failed.har` and two diagnostic JSON exports. Raw captures stay
outside the repository because they contain room credentials and network details.
The HAR records successful state/ICE/ticket HTTP responses and a WebSocket 101.
Eight offer sends each receive `signal_ack` with `delivered: false`; no answer is
recorded. This establishes missing remote signaling delivery, not TURN failure.
The host export has peers that never leave `new`. The other export contains no
peers, but predates the captured attempt; it cannot establish why the remote socket
was absent during that later attempt. Both are not a synchronized two-peer trace.

A second role-swapped retry used the same old deployed build. The export ending
07:20:58Z has no peer connections; the export ending 07:21:57Z contains only the
old peers created at 07:11/07:12. The user confirms both sides pressed connect.
Read-only inspection of the local browser showed `negotiation_timeout` in the
new room. The remote host's error was not retained. Two older HTTP transport
failures in the local export precede this retry and cannot explain it by themselves.
Thus the second attempt stopped before peer creation; its host-side cause remains
unresolved. Do not attribute it to an unpressed button or claim TURN is broken.

The current lobby only opened its signaling socket from the explicit connection
button. State polling never responded to a host negotiation. A guest who joined
and waited therefore could not receive the host offer. Eight backoff attempts
exhausted in approximately 20 seconds. Separately, the service deliberately clears
negotiation on socket replacement, but a waiting host never recreated it.

## Change and scope

A guest now responds once to each live lobby negotiation discovered by state
polling/push. Busy operations, active connections, expired requests, match epochs,
missing members, and leaving the room block automatic startup. Duplicate state
updates do not cause an endless retry loop. A fresh host request permits another
attempt. Manual connection remains available.

When a guest socket replacement clears the negotiation, the host recreates its
peer and offer within the original 60-second deadline. No server contract change,
combat behavior, source inputs, or gameplay parity gate is involved. Failure text
now distinguishes undelivered invitations, waiting for the host, and channel timeout.

Exports now include an `onlineLobby` snapshot with role, startup stage, blocking
flags and the last error. Connection errors also enter the existing persistent
critical-event buffer through a warning. Only fixed fields and validated machine
codes are recorded, excluding room IDs, invitations, credentials, SDP and URLs.
This addresses the missing evidence in the second retry without guessing its cause.
