## Identity schema: evidence requirements, not invented native layout

`identity-requirements.json` explicitly leaves native_location, verified_type and independent_witness **null** for every role:

- loaded body: native binding to SWF/definition/action/clip-action provenance;
- owner and owner generation: definition/placement plus independent lifetime continuity across replacement and reuse;
- closure generation: loaded callback/function with replacement-safe identity;
- activation: dispatcher entry identity that distinguishes reentrancy/recursion;
- transition edge: actual receiver/argument/activation at a justified native goto/removal boundary;
- dispatcher outcome: matching outer continuation/outcome, with missing/interrupt/fallthrough distinguished;
- body target: independently witnessed relation to generation-bound target body.

These are obligations, not observed fields. Paths, depth, raw pointers, instruction addresses, timestamps, source serials and observer counters alone cannot fill them. A root mailbox would manufacture an association if intervening transitions are unobserved. The plan checker rejects inserting speculative offsets/types or marking the schema verified; it is deliberately not a generic proof-import API. New independent evidence would require a separate reviewed revision.
