# r31: option response identity and effective/reset semantics

This offline review adds narrower source findings to r30's initialization ledger. It does not execute a request or establish that a race, stale read or option failure actually occurred on Flash32. All links below pin Apache Flex commit `ba414443032b49c45ff11b61db452c8a8f428bd8`; r29 retains PlayerSession/DManager, and r31 retains DMessageCounter unchanged.

## What the client actually accepts

`simpleRequestResponseMessage` samples the input count for a message type and target isolate, sends the request, then accepts an increment of that count as a response. The reviewed routine does not compare an echoed option name, value or unique request token. `DMessageCounter.messageArrived` routes isolate counters and increments counts by message type. This is a concrete **client acceptance rule**, not a producer guarantee that replies cannot be delayed, unsolicited or interleaved. [PlayerSession 2093–2184](https://github.com/apache/flex-sdk/blob/ba414443032b49c45ff11b61db452c8a8f428bd8/modules/debugger/src/java/flash/tools/debugger/concrete/PlayerSession.java#L2093-L2184), [DMessageCounter 124–182](https://github.com/apache/flex-sdk/blob/ba414443032b49c45ff11b61db452c8a8f428bd8/modules/debugger/src/java/flash/tools/debugger/concrete/DMessageCounter.java#L124-L182).

`InOption` decodes two strings into `m_options.put(name,value)`. The map is a manager-level map keyed by name, not a request/generation ledger. `getOption` requests a name, waits for an InOption count change, then reads that name from the map. `sendOptionMessage` sends name/value and waits for InOption, but discards the boolean result. Neither path establishes before/effective/after state or a restoration transaction. These are separate obligations; a returned cached string is not by itself fresh readback. This does not prove that wrong options are returned in normal operation. [DManager 104–116](https://github.com/apache/flex-sdk/blob/ba414443032b49c45ff11b61db452c8a8f428bd8/modules/debugger/src/java/flash/tools/debugger/concrete/DManager.java#L104-L116), [1550–1555](https://github.com/apache/flex-sdk/blob/ba414443032b49c45ff11b61db452c8a8f428bd8/modules/debugger/src/java/flash/tools/debugger/concrete/DManager.java#L1550-L1555), [PlayerSession 1975–1984](https://github.com/apache/flex-sdk/blob/ba414443032b49c45ff11b61db452c8a8f428bd8/modules/debugger/src/java/flash/tools/debugger/concrete/PlayerSession.java#L1975-L1984), [2078–2091](https://github.com/apache/flex-sdk/blob/ba414443032b49c45ff11b61db452c8a8f428bd8/modules/debugger/src/java/flash/tools/debugger/concrete/PlayerSession.java#L2078-L2091).

There is another implicit outgoing path beyond r30's timeout heartbeat: receiving `InProcessTag` makes `postMessageArrived` send `OutProcessedTag` to the target isolate. The client comment describes this as necessary for player progress. That establishes the automatic client reply and its stated intent, **not** exact Flash32 AVM1 scheduling/blocking semantics or evidence that such a message occurred. A preservation review cannot assume every incoming message may safely be ignored, nor that replying is behavior-neutral. [PlayerSession 2300–2305](https://github.com/apache/flex-sdk/blob/ba414443032b49c45ff11b61db452c8a8f428bd8/modules/debugger/src/java/flash/tools/debugger/concrete/PlayerSession.java#L2300-L2305).

## No effective reset proof

The inspected client callback for disconnection changes local connection state and notifies event waiters; it contains no producer-state readback. An InExit sets local connected=false. Neither is a reset certificate. No new producer evidence shows whether any particular option resets, persists or is ignored. [PlayerSession 2229–2234](https://github.com/apache/flex-sdk/blob/ba414443032b49c45ff11b61db452c8a8f428bd8/modules/debugger/src/java/flash/tools/debugger/concrete/PlayerSession.java#L2229-L2234), [2294–2298](https://github.com/apache/flex-sdk/blob/ba414443032b49c45ff11b61db452c8a8f428bd8/modules/debugger/src/java/flash/tools/debugger/concrete/PlayerSession.java#L2294-L2298), [DManager 1066–1070](https://github.com/apache/flex-sdk/blob/ba414443032b49c45ff11b61db452c8a8f428bd8/modules/debugger/src/java/flash/tools/debugger/concrete/DManager.java#L1066-L1070).

Required independent evidence is a version-bound producer contract for option response correlation, effective-value meaning, defaults and disconnect restoration, plus lifecycle-ID namespace/reuse and progress-message semantics. Matching names/counts alone cannot manufacture it. No protocol implementation, transaction wrapper or connection experiment is added; all preservation controls remain unexecuted.
